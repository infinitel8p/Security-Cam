# Dashboard

After completing the setup, open the dashboard in your browser:

```
http://<raspberry-pi-ip>:3000
```

If you're connected to the Pi's Access Point, you can use any of these:

| URL | Note |
| --- | --- |
| `http://dashboard.cam` | Custom hostname, redirected via captive portal (no port needed) |
| `http://192.168.4.1:3000` | Direct IP access |
| `http://dashboard.cam:3000` | Custom hostname with explicit port |

:::tip
`http://dashboard.cam` (without port) works because the captive portal redirects port 80 to 3000. This is the easiest to remember but may be slightly slower due to the redirect.
:::

:::note
The frontend auto-detects the backend and MediaMTX URLs from the hostname you're visiting. No `.env` configuration is needed on the Pi. Only set `PUBLIC_BACKEND_URL` and `PUBLIC_MEDIAMTX_URL` in `server/.env` if you're running the frontend dev server on a separate machine.
:::

The dashboard is organized into three pages.

## Home

The main page shows everything at a glance:

- **Live Feed** - real-time camera view via WebRTC, with manual recording controls (start/stop)
- **Backend Status** - online/offline indicator for the Flask backend, polled every 10 seconds
- **Sensor Status** - current sensor type, state (Armed / Triggered / Suppressed / Disabled), and GPIO pin. See [sensor states](./sensors#sensor-states) for what each means
- **Connection Status** - how many tracked Bluetooth and WiFi devices are online
- **System Health** - CPU temperature, load, RAM usage, storage, uptime, and throttle status
- **Activity Timeline** - last 7 days of events: sensor triggers, recording events, stream disconnects. Rapid sensor pulses within 5 minutes are collapsed into a single entry with a count
- **Access Log** - last 72 hours of device arrivals and departures
- **Health Tracker** - 72-hour system health chart (48 time slots, colour-coded ok/warn/critical)
- **Event Heatmap** - ~6-month activity heatmap showing event intensity by day of week
- **Setup Checklist** - first-run onboarding guide (add devices, enable sensor). Dismissible once complete

## Archive

Browse and manage recorded videos:

- Videos are displayed in a grid, grouped by date, and can be filtered by time range or sorted
- Click a video to stream it directly in the browser
- Download or delete individual recordings

## Settings

Configure the system without touching config files. The settings page has a sidebar with five sections:

- **Appearance** - switch between dark, light, and system theme. Choose the dashboard language (English, German, French, Spanish, Italian). Toggle the scan line overlay on the live feed.
- **Camera** - adjust stream resolution, framerate, and rotation (display-only or hardware via MediaMTX). Pick from quality presets tuned for the Pi Zero 2 W, or set custom resolution and FPS.
- **Storage** - choose where recorded videos are stored on the Pi. Enable [auto-delete](./storage) to prevent the SD card from filling up.
- **Devices** - add or remove tracked Bluetooth and WiFi devices. Three ways to add a Bluetooth device: scan for nearby devices, [make the Pi discoverable](#bluetooth-pairing-from-the-dashboard) so your phone can find it, or enter a MAC address manually. Online/offline status is shown per device. Tracked devices are used for presence detection — if any are nearby, sensor triggers are ignored.
- **Recording Sensors** - select and configure the active sensor type, set the GPIO pin and hold timeout, adjust [calibration](./calibration), test wiring with a live sparkline, and enable/disable auto-recording. See the [sensors guide](./sensors) for details.

All settings changes show a toast confirmation when saved successfully.

## Bluetooth pairing from the dashboard

You don't need SSH or the setup script to pair Bluetooth devices after initial setup. The **Settings > Devices** section in the dashboard supports two pairing methods:

1. **Scan** — the Pi scans for nearby Bluetooth devices for ~20 seconds. Pick your device from the results. Works best when your device's Bluetooth visibility is turned on (on iPhone, keep Settings > Bluetooth open during the scan).

2. **Make Pi discoverable** — the Pi makes itself visible for 90 seconds. Open Bluetooth settings on your phone and pair with the Pi from there. This is useful when your device doesn't show up in scans, which is common with iPhones and some Android devices.

Both methods auto-accept pairing prompts, trust the device, and register it for presence detection. You can also enter a MAC address manually if you know it.

:::tip
For the initial setup before the dashboard is running, use the [`pair_bluetooth.sh`](../setup/bluetooth) script over SSH instead.
:::

## How auto-recording works

When a trigger sensor is enabled:

1. The sensor fires (door opens, motion detected, vibration felt, etc.)
2. The system checks if any tracked Bluetooth or WiFi device is nearby
3. If nobody is home, recording starts automatically
4. When the sensor releases, recording continues for the configured hold timeout (default 10 seconds) to prevent gaps from brief interruptions
5. After the hold timeout, recording stops

Manual recording from the dashboard is always allowed, regardless of sensor state or presence detection.

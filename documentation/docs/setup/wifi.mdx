# WiFi Setup

This guide will help you set up a WiFi Access Point on your Raspberry Pi while keeping it connected to your home WiFi network. The Pi will use a single WiFi chip to run both connections simultaneously using NetworkManager.

:::note
Both the Access Point and the home WiFi connection must operate on the **same channel** since the Pi only has one WiFi radio. The AP will use the same channel as your home WiFi.
:::

## Find your WiFi channel

Run the following command to check your current WiFi connection and its channel:

```bash
iw dev
```

You should see an output similar to this:

```bash title="Example Output:"
pi@securitycam:~ $ iw dev
phy#0
        Unnamed/non-netdev interface
                wdev 0x2
                addr 2e:cf:xx:xx:xx:xx
                type P2P-device
                txpower 31.00 dBm
        Interface wlan0
                ifindex 2
                wdev 0x1
                addr 2c:cf:xx:xx:xx:xx
                ssid FRITZ!Box 6690
                type managed
                channel 6 (2437 MHz), width: 20 MHz, center1: 2437 MHz
                txpower 31.00 dBm
```

Note the **channel number** (`channel 6` in this case) — you will need it later.

## Create the virtual AP interface

The Pi's WiFi chip supports running a second virtual interface for the Access Point. We create a systemd service so this interface is automatically set up on every boot before NetworkManager starts.

1. Create the service file:

   ```bash
   sudo nano /etc/systemd/system/create-ap0.service
   ```

2. Paste the following content:

   ```ini title="/etc/systemd/system/create-ap0.service"
   [Unit]
   Description=Create Virtual WiFi Interface ap0
   Requires=sys-subsystem-net-devices-wlan0.device
   After=sys-subsystem-net-devices-wlan0.device
   Before=NetworkManager.service

   [Service]
   Type=oneshot
   ExecStart=/sbin/iw dev wlan0 interface add ap0 type __ap
   RemainAfterExit=yes

   [Install]
   WantedBy=multi-user.target
   ```

3. Save and exit, then enable and start the service:

   ```bash
   sudo systemctl enable create-ap0.service
   sudo systemctl start create-ap0.service
   ```

## Create the Access Point

Use NetworkManager to create the AP connection. Replace the values as needed:

- `SecurityCam` — your desired network name (SSID)
- `YourPasswordHere` — your desired WiFi password
- `channel 6` — the channel from the first step

```bash
sudo nmcli connection add type wifi ifname ap0 con-name SecurityCamAP \
  autoconnect yes \
  802-11-wireless.mode ap \
  802-11-wireless.band bg \
  ipv4.method shared \
  wifi-sec.key-mgmt wpa-psk \
  wifi-sec.pairwise ccmp \
  wifi-sec.group ccmp \
  wifi-sec.proto rsn \
  ssid "SecurityCam" \
  ipv4.addresses 192.168.4.1/24 \
  802-11-wireless.channel 6 \
  wifi-sec.psk "YourPasswordHere"
```

:::info
The `ipv4.method shared` setting is the key here — NetworkManager automatically handles DHCP, DNS, NAT, and IP forwarding for you. No need for separate `dnsmasq`, `hostapd`, or `nftables` configuration.
:::

Bring the AP up:

```bash
sudo nmcli connection up SecurityCamAP
```

## Verify the setup

Check that both interfaces are connected:

```bash
nmcli device status
```

You should see both `wlan0` and `ap0` as connected:

```bash title="Example Output:"
DEVICE         TYPE      STATE                   CONNECTION
ap0            wifi      connected               SecurityCamAP
wlan0          wifi      connected               netplan-wlan0-FRITZ!Box 6690
lo             loopback  connected (externally)  lo
p2p-dev-ap0    wifi-p2p  disconnected            --
p2p-dev-wlan0  wifi-p2p  disconnected            --
```

Try connecting a device (e.g. your phone) to the Access Point. You should be able to access the internet through it.

## Reboot and confirm persistence

```bash
sudo reboot
```

After reconnecting via SSH, run `nmcli device status` again to confirm both connections survived the reboot.

You can also SSH into the Pi through the Access Point:

```bash
ssh pi@192.168.4.1
```

:::note
These instructions were tested on Raspberry Pi OS Trixie with a Raspberry Pi Zero 2 W.
:::

:::caution
Running simultaneous AP and client on a single WiFi chip halves the available bandwidth since the radio time-shares between both roles. If you experience connection drops or need more bandwidth, consider using a USB WiFi dongle for one of the connections.
:::
